# ADR-0020: Copies of the lab add one suffix to the names that must be unique across Azure

- **Status:** Accepted
- **Date:** 2026-11-23

## Context

The lab should be reusable: anyone can fork it and deploy their own copy into a new trial tenant and
subscription ([QUICKSTART](../../QUICKSTART.md)).

Every name comes from `prefix` (default `lab`, [naming](../naming.md)). Most names only need to be unique
inside one subscription, repository, HCP organisation or tenant, so a copy can keep `lab` for them. Three
must be unique across all of Azure:

| Resource | Why it is global |
|---|---|
| Report store, a storage account | `<name>.blob.core.windows.net` |
| Foundry account | Its custom subdomain, `<name>.openai.azure.com` |
| API Management, and its public IP label | `<name>.azure-api.net`, and `<label>.australiaeast.cloudapp.azure.com` |

A deleted Foundry account or API Management service can keep its name for a while, so even the original
lab could not always reuse its own names after a teardown.

Before this decision, the GitHub owner and apply reviewer also defaulted to the original maintainer, so a
copy's bootstrap would have targeted the wrong account.

## Options considered

| Option | For | Against |
|---|---|---|
| Copies change `prefix` | One input | The prefix is also in dozens of workflow environment names, every HCP workspace and every Entra object, none of which can clash; changing it touches everything for no gain |
| A random suffix generated by Terraform | Nothing to choose | The runner, the test scripts and the agent build the same names without reading state, so they would need it passed to them anyway; a random value is harder to type and troubleshoot |
| One chosen `unique_suffix` on the three global names | Small change, names stay readable, the original lab's names do not change | One more input to set, in two places |

## Decision

Add `unique_suffix` (0 to 3 lowercase letters or digits, default empty) to the three global names only.
Bootstrap takes it from its git-ignored variable file. Level 3, the test scripts and the ops agent take it
from the repository variable `LAB_UNIQUE_SUFFIX`. With the suffix empty, the original lab plans no change.

Three characters keep the storage name within 24 characters with the longest allowed prefix.

The GitHub owner and apply reviewer are now required inputs with no default. Helper scripts take the
repository from the clone. A read-only preflight script (`bootstrap/scripts/preflight.sh`) checks tools,
sign-ins, the trial and its spending limit, the tenant, and the availability of each global name before
anything is created.

## Risks accepted

| Risk | Why it is accepted | Mitigation, or how we would notice |
|---|---|---|
| The suffix is set in two places and they disagree | Bootstrap is person-run and cannot read GitHub variables at plan time | The preflight checks the repository variable; a mismatch fails the agent's first call to the report store, loudly |
| Three characters can clash | About 46,000 values for a handful of copies | The preflight checks every global name before the first apply |
| A copy is not yet proven end to end | CI and the mock tests cover the names; a full deployment needs a new free account | QUICKSTART states it under known limits |

## Consequences

- A copy changes one variable, not the naming scheme.
- The original lab is unchanged: every plan for it shows no changes.
- If names are ever built in a fourth place, it must take the suffix too. `tests/gateway/lib.sh` and
  `agents/opsagent/opsagent/config.py` are the places today, and both have tests.
- Revisit if a copy needs another region: the region code is still fixed at `ae` in names.
